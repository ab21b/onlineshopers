# Прогноз покупки в интернет-магазине

Исследование на датасете **Online Shoppers Purchasing Intention**: по данным о сессии пользователя предсказываем, закончится ли она покупкой (бинарная классификация).

## Датасет

[Online Shoppers Purchasing Intention Dataset](https://www.kaggle.com/datasets/imakash3011/online-shoppers-purchasing-intention-dataset) - 12 330 сессий интернет-магазина, 17 признаков (число и длительность посещённых страниц, `BounceRates`, `ExitRates`, `PageValues`, месяц, тип посетителя, тип трафика и др.), целевая переменная `Revenue`.

**Почему этот датасет:**
- понятная бизнес-задача (будет ли покупка), результат легко интерпретировать;
- сильный дисбаланс классов (около 15% покупок): нельзя ограничиться accuracy, приходится смотреть на F1, ROC-AUC, PR-AUC;
- смесь числовых и категориальных признаков, есть сильно коррелирующие пары, поэтому можно проверить гипотезы про препроцессинг, важность и отбор признаков;
- нет пропусков, но есть дубликаты, что позволяет аккуратно построить пайплайн без утечек.

## Гипотезы 

1. **H1.** Из-за дисбаланса классов таргета Логистическая регрессия будет работать по accuracy не сильно лучше тривиального классификатора, который всегда предсказывает 0.
2. **H2.** Random Forest обойдёт одиночное дерево решений по F1 и ROC-AUC, потому что усреднение многих деревьев снижает переобучение.
3. **H3.** При глубине дерева около 10 начнётся переобучение.
4. **H4.** F1-macro будет заметно ниже accuracy из-за дисбаланса классов.
5. **H5.** Признак `PageValues` будет самым важным по feature importance дерева решений.
6. **H6.** `BounceRates` и `ExitRates` сильно коррелируют (больше 0.9), поэтому удаление одного из них не ухудшит качество логистической регрессии.
7. **H7.** Отбор 5 лучших признаков через `SelectKBest` не ухудшит качество модели.
## Структура работы

- **EDA:** пропуски, дубликаты, дисбаланс классов, распределения, корреляции, boxplot по классам, доля покупок по категориям.
- **Подготовка данных:** удаление дубликатов, `pd.get_dummies` для категорий, `log1p` для скошенных признаков, `StandardScaler` внутри `Pipeline` (без утечки данных), стратифицированное разбиение train/test 80/20.
- **Модели:** логистическая регрессия, дерево решений, Random Forest (и Dummy как нижняя граница).
- **Метрики:** accuracy, precision, recall, F1, F1-macro, ROC-AUC, PR-AUC, confusion matrix.
- **Кросс-валидация:** `StratifiedKFold(5)`.
- **Подбор гиперпараметров:** `GridSearchCV` (LogReg, дерево), `RandomizedSearchCV` (Random Forest).
- **Отбор признаков:** `SelectKBest` (F-статистика и mutual information), RFE, все внутри `Pipeline`.

## Краткие результаты

| N | Результат |
|---|---|
| H1 | **подтвердилась** || H2 | **частично** | Random Forest лучше дерева по ROC-AUC (0.932 против 0.924), но по F1 разница в пределах шума. Заметный выигрыш только по PR-AUC. |
| H3 | **подтвердилась** | При глубине 10 train accuracy 0.952, CV accuracy 0.887. Максимум CV на глубине 5, дальше качество падает. |
| H4 | **подтвердилась** | F1-macro ниже accuracy примерно на 10 п.п. (у Dummy на 39 п.п.). Лучшая модель пропускает около 38% покупателей. |
| H5 | **подтвердилась** | `PageValues` - топ-1, importance дерева 0.74. |
| H6 | **подтвердилась** | Корреляция 0.90, удаление одного из признаков не меняет ROC-AUC (0.9124 / 0.9125 / 0.9126). |
| H7 | **частично** | F1 не меняется, но ROC-AUC при k=5 у `SelectKBest` падает на 0.03 (у RFE на 0.006). |

**Итог:** лучшая модель Random Forest. Самый важный признак `PageValues`. Это метрика Google Analytics, которая считается по транзакциям, поэтому для прогноза до покупки она вряд ли была бы доступна.
